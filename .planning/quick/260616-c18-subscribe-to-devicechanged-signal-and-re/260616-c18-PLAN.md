<objective>
Consume the daemon's new additive `DeviceChanged` D-Bus signal on the
unchanged `org.usbeehive.Devices5` interface so USBee re-snapshots the
tile when a *present* device/port's curated state changes — without
firing any desktop notification. This is the USBee consumer half of the
stale "Charging 15W" fix; the daemon half already shipped in usbeehive
0.10.x (additive signal, no wire bump, no `MIN_USBEEHIVE_VERSION` change).

Purpose: On a benign AC unplug the Type-C port stays present, so none of
DeviceAdded/DeviceRemoved/CapabilityDegraded/CapabilityRestored fire and
the tile never reloads — it keeps showing a stale wattage. DeviceChanged
is the missing re-snapshot trigger for present-port transitions.

Output: DeviceChanged added to both XML copies (byte-equal preserved), a
non-notifying re-snapshot handler, a regression test, and a CHANGELOG entry.
</objective>
