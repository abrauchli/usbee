# Quick Task 260916-2qs — Fold `[Unreleased]` into `[2.9.0]`, then tag and push v2.9.0

## Problem

`260915-mpf` cut v2.9.0 (commit `2098719`: `metadata.json` → `14` /
`2.9.0`, new `## [2.9.0] — 2026-09-15` section) but deliberately held
back the tag and the push. Six commits then landed *on top of* that
release commit, three of them real user-visible popover UX fixes, and
`260915-une` wrote them up under a fresh `## [Unreleased]`.

So the tree now holds a v2.9.0 release commit that is neither tagged
nor pushed, plus five `Fixed` bullets that the 2.9.0 build on disk
already contains. Tagging as-is would ship a release whose notes omit
the fixes it actually carries.

## Decision (made by the operator, not inferred)

**Fold, do not bump.** The `[Unreleased]` entries move into the
existing `## [2.9.0] — 2026-09-15` section; `metadata.json` stays at
`2.9.0` / `14`. Nothing named 2.9.0 was ever published — no tag, no
GitHub Release, no EGO submission — so there is no released artifact
whose notes this would retroactively rewrite. Folding makes the
already-installed 2.9.0 build's label truthful rather than shipping a
2.9.1 that differs from 2.9.0 by nothing but a changelog edit.

## Date

The section keeps **2026-09-15**. All six post-release commits are
dated 2026-09-15 (`git log --format=%ad --date=short 2098719..HEAD`);
only today's wall clock is 2026-09-16. The date names when the work
landed, not when the tag was cut.

## Subsection placement

`[Unreleased]` carries a single `### Fixed` block (five bullets).
`[2.9.0]` carries `### Added`, `### Changed`, `### Removed` and **no
`### Fixed`**. The five bullets therefore append as a new `### Fixed`
subsection placed *after* `### Removed`, which is Keep a Changelog
order (Added, Changed, Deprecated, Removed, Fixed, Security) and the
order the rest of this file already follows. No duplicate subsection
headers are created; no prose is rewritten — the bullets move verbatim.

## Tasks

1. **Edit `CHANGELOG.md` only.** Move the five `### Fixed` bullets out
   of `[Unreleased]` and into `[2.9.0]` after `### Removed`. Leave
   `## [Unreleased]` present with no body, directly followed by a blank
   line and `## [2.9.0]` — byte-for-byte the shape `2098719` left (see
   `git show 2098719:CHANGELOG.md | head -12`). The `[2.9.0]:`
   reference link at the bottom already exists; leave it untouched.
   Net diff must be pure movement: **0 words of prose changed**.
2. **Confirm `metadata.json` is untouched** — still `14` / `2.9.0`.
   This task bumps nothing.
3. **Commit `CHANGELOG.md` alone.** Explicit path, never `git add -A`
   or `commit -a`: `.gsd/` and `.planning/quick-batches/` are untracked
   and must stay out. GSD docs artifacts commit separately (Step 8).
4. **Tag** `v2.9.0`, annotated, body = the `[2.9.0]` section. The tag
   name must equal `metadata.json` `version-name` exactly —
   `.github/workflows/release.yml` asserts this and fails otherwise.
5. **Push** `master`, then the tag. Tag push is what triggers the
   release workflow.
6. **Confirm the workflow started** via `gh run list`.
