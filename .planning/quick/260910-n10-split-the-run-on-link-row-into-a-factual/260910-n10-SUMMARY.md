# Summary

## What changed

The property panel's `Link` row carried three claims in one value string
and wrapped to three lines. It now carries one fact per row:

```
before   Link            480 Mb/s (USB 2.1) — could run at
                         SuperSpeed 5 Gbps on a faster port
         Max bus power   350 mA

after    Link            480 Mb/s
         Capability      SuperSpeed 5 Gbps
         Max bus power   350 mA
```

## Provenance of the bad string

`src/popover.js:451` (pre-change) composed `_('%s — could run at %s on a
faster port')` from two tokens. **Extension-composed, not daemon-supplied** —
the daemon contributes only `usb_capable_speed` (the label "SuperSpeed
5 Gbps") and the `usb_link_verdict` enum. The remedy clause was USBee's own
invention and was therefore fixable here.

## Correctness

The remedy is withdrawn, not reworded. The device that prompted this is a
Realtek RTL8153 behind a Genesys GL850 (`05e3:0608`) — a USB-2.0-only hub
inside a Samsung monitor. It is capped by that hub, not by the port; no port
on the machine can help. USBee cannot see the ancestor chain (that needs the
daemon's proposed `link.culprit` / `link.culprit_id`), so the new row states
the device's own BOS-declared capability and stops. Same discipline as commit
`18aff96`, which withdrew `ss-never-linked` / `ss-unstable` / `ss-elsewhere`
for the same reason.

**Deliberately not claimed:** where the capability could be reached; that a
faster port, a different cable or removing a hub would help; that anything is
at fault; that the shortfall is fixable at all.

## Decisions taken without the user (audit these)

- **`Capability` over the user's `Achievable` sketch.** "Achievable" asserts
  the speed is reachable somewhere — the exact inference USBee cannot make.
  `Capability` is already the panel's word for this concept: `label-table.js`
  binds it to `usb_bos_suppressed`, whose value is the complementary "unknown
  — the kernel skips this device's capability descriptor". The two states are
  mutually exclusive, so one label covers both and no new translatable string
  was added. Also rejected: `Device rating` (collides with "Max bus power" —
  "rating" reads as a power rating), `Rated speed` (ambiguous whether the link
  or the device is rated).
- **`(USB 2.1)` dropped from the Link row.** `usb_version` is the daemon's
  canonicalised `bcdUSB` (`summary.rs:250`, `2.10` → `"2.1"`); `bcdUSB 2.10`
  declares only that the device carries a BOS descriptor, and USB 2.1 is not a
  specification. It read like an actionable version number beside a rate that
  already said the same thing more precisely. Wire value untouched.
- **`AtCapability` and `Degraded` Link-row suffixes kept.** `— full
  capability` is short and its Capability row is suppressed anyway; `— below
  the %s this device needs` quotes the *functional floor*, a different figure
  from the capability, and splitting it would collide with the existing
  tech-tier `Needs at least` row.
- **Suppression rule is uniform**, so `Degraded` devices now also gain a
  Capability row (previously their capability was not shown at all — only the
  floor). Truthful and useful, but it is new information on the warning tier.

## Suppression rule

`deriveShowCapability()` in `src/link-verdict.js`. Render iff
`usb_capable_speed` is non-empty AND the capability exceeds the negotiated
rate — decided by `usb_capable_speed_mbps` when present, otherwise by a
`BelowCapability` / `Degraded` verdict. `AtCapability`, an unrecognised
verdict, a suppressed BOS, and a capability at or below the link all render
nothing.
