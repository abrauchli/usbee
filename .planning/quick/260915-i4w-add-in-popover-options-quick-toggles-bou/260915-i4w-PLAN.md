# Quick Task 260915-i4w — In-popover Options toggles + "Hide built-in devices" filter

## Problem

USBee's user-facing filter switches live only in the preferences window, so
changing a filter costs a window launch away from the popover the user is
already looking at. Competitive read of `bjuergens/whatcable-gnome`.

Second gap: USBee renders the daemon's `mount` property as a detail row but
never filters on it, so soldered-down hardware (webcam, fingerprint reader,
Bluetooth radio) permanently occupies the device list.

## Decisions (inferred — human unavailable)

- **D-1 — New key is `hide-builtin-devices`, default `false`.**
  Matches the `hide-*` naming and polarity of the existing `hide-empty-ports`.
  Default `false` because (a) a default that hides devices silently omits
  hardware on first run and on upgrade from v2.8.0, and (b) built-in devices
  are *real devices*, unlike hubs (`show-hubs` defaults to hiding) which are
  pure topology noise. Non-destructive default = no behaviour change on
  upgrade.
- **D-2 — Predicate is `mount === 'fixed'`, verified at the daemon source.**
  usbeehive `src/summary.rs:645` pushes `("mount", dev.removable)` *only*
  when `dev.removable` is exactly `"removable"` or `"fixed"`; `"unknown"`
  and `""` are dropped (`src/usb.rs:71`). So absence means "the kernel did
  not say", which is not "built in" and must not be filtered on.
- **D-3 — Built-in devices with an issue stay visible.** Same escape hatch
  `show-hubs` uses (quick task 260905-b0s): the header subtitle reports an
  issue count, so hiding an issue-carrying row would name a fault the user
  cannot reach. Composition rule, not a nicety.
- **D-4 — Predicate lives in `src/link-verdict.js`** (zero-import module) so
  bare-gjs CI can unit-test it. `popover.js` imports gnome-shell resources
  and can only be guarded structurally.
- **D-5 — Options is a `PopupSubMenuMenuItem`,** not four always-visible
  rows: four flat switches would push the device list down and fight the
  project's glanceable ethos.

## Tasks

1. **Schema** — add `hide-builtin-devices` (`b`, default `false`) to
   `schemas/org.gnome.shell.extensions.usbee.gschema.xml`.
2. **Predicate** — add `isBuiltInDevice()` to `src/link-verdict.js`.
3. **Popover** — consume the new filter in `populateDeviceRows()` (composing
   with the existing two, with the D-3 escape hatch); add an exported
   `buildOptionsSection()` returning a submenu of four `PopupSwitchMenuItem`s
   two-way bound to GSettings.
4. **Tile** — mount the Options submenu above the Preferences row; rebuild
   the device list when any filter key changes; track handlers in
   SignalRegistry.
5. **Prefs** — add the matching `Adw.SwitchRow` to the General group.
6. **Tests** — extend `tests/forward-compat.test.js`: unit tests for
   `isBuiltInDevice`, structural guards for the popover/tile/prefs/schema
   wiring.
7. **CHANGELOG** — entry under `## [Unreleased]`.

## Verification

- `gjs -m tests/forward-compat.test.js` (plus the other three CI suites).
- `glib-compile-schemas` on the schemas dir — the new key must compile.
- Prefs window end-to-end mid-session (`pkill -f org.gnome.Shell.Extensions`,
  then `gnome-extensions prefs usbee@bitcreed.us`), and `gsettings` round-trip
  on the new key.
- Popover cannot be verified without a Shell restart — out of scope here.

## Constraints

- No version bump, no CHANGELOG released-section edits, no tag, no push.
- Every user-visible string through gettext.
- Documented Quick Settings / PopupMenu API only.
- No daemon change; no `/sys` or udev access.
