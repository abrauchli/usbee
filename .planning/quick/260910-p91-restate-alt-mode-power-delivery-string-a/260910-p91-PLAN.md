# Restate the alt-mode PD string as a condition; correct the EGO framing in CLAUDE.md

Two independent changes, one task. They share no file.

## Part 1 — alt-mode Power Delivery: state the condition, drop the imperative

### Problem

`src/popover.js:612` renders, for the alt-mode `no_usb_pd` case:

```
Alt mode failed: no USB-PD on this connection — use a USB-C port and cable
that support Power Delivery
```

This is the last remedy-shaped string in the UI. Three prior quick tasks
removed the others: `18aff96` (connector hints), `260910-n10` (the
`Link`/`Capability` split), `260910-o99` (the notification body and the
`Fix` row). `260910-o99` flagged this one (claim #3 in its inventory) as
"materially different — report, do not change", because the *cause* is
daemon-asserted (`usb_altmode_state == Unsuccessful` ∧ `usb_altmode_failure`
contains `no_usb_pd`), not inferred from absent topology.

That distinction still holds, and it is why this is a **mood** change and
not a deletion. `no_usb_pd` genuinely means Power Delivery is not present on
this connection, and "a PD-capable port and cable" is definitionally what is
missing — not a guess. What is wrong is the imperative. On the development
machine there is no PD controller at all (`/sys/class/typec` absent), so
"use a USB-C port and cable that support Power Delivery" resolves to "buy a
different motherboard": an instruction to do something the user may have no
path to, phrased as though they do.

### Decisions

- **D-1 — Restate, do not delete.** The information is sound; only the mood
  is wrong. The row keeps its always-visible, amber treatment.
- **D-2 — Match the voice the three prior tasks settled on.** That voice is
  `fact — elaboration`, joined by an em dash, declarative throughout:
  - `popover.js` connector hint: *"SuperSpeed did not come up on this link —
    the cause could be the cable, the port, or a hub in between"*
  - `notifier.js:348`: *"The cause could be the cable, the port, or a hub in
    between"*
  - `popover.js` Link row: *"%s — below the %s this device needs"*

  The new string therefore reads:

  ```
  Alt mode did not start — this connection does not provide USB Power
  Delivery, which needs both a port and a cable that support it
  ```

  "did not start" mirrors "did not come up". The PD requirement is stated as
  a property of Power Delivery, not as a thing the user is told to go get.
- **D-3 — Keep the `deriveAltMode().actionable` field name.** It is pinned by
  four assertions in `tests/forward-compat.test.js:444-466` and it selects a
  row, which is still the right behaviour. Its docstring is corrected to say
  what it now means — "the one combination worth an always-visible row" —
  rather than "genuinely actionable", which asserts a remedy exists.

### Sibling audit (done before planning)

- Alt-mode value strings in `src/label-table.js:150-154` (`not attempted`,
  `active`, `failed`, `error`) are bare facts. **Clean, unchanged.**
- `src/label-table.js:69-70` labels (`Alt mode`, `Alt mode failure`) are
  nouns. **Clean.**
- Full grep of every `_('…')` in `src/*.js` + `prefs.js` for imperative
  verbs (`use a`, `move it`, `try`, `plug`, `switch to`, `connect it`,
  `swap`, `replace the`, `should`, `instead`, `check your`, `make sure`)
  returns **one** hit, and it is a false positive: `_('Plug orientation')`
  in `label-table.js:44`. So this is genuinely the last one.
- Three comments state the remedy as fact and are corrected so the belief is
  not re-seeded (the same treatment `260910-o99` gave four comments in
  `notifier.js`):
  - `src/popover.js:362` — "with exactly one actionable case"
  - `src/popover.js:588-594` — "The single actionable combination … is a
    cable or port that cannot do USB Power Delivery"
  - `src/link-verdict.js:298-302` — "The one genuinely actionable
    combination …"

## Part 2 — correct the EGO framing in CLAUDE.md

### Problem

USBee is not published on extensions.gnome.org, and the user has confirmed
it is not. CLAUDE.md instructs otherwise:

- Release Process step 6 directs the maintainer to download the zip and
  submit it at <https://extensions.gnome.org/upload/>. That step describes
  work that does not happen.
- The Release Process preamble frames EGO submission rules as the reason
  there is no binary build step, and `version` as "increment by 1 per EGO
  submission".
- The mirrored stack tables ("What NOT to Use") present EGO review as a live
  gate: "Rejected on submission", "EGO reviewers will reject it", "EGO
  reviewers reject this".

### Decisions

- **D-4 — Narrow, not wholesale.** The constraints themselves ("no bundled
  binaries", "no minified/obfuscated JS", "documented API surface only") are
  good practice on their own merits and keep future submission possible at
  zero cost. Only their *status* is reframed.
- **D-5 — Neutral on intent.** The user has not said whether EGO submission
  is abandoned or deferred. Every new sentence must be true under both
  readings: "not currently submitted, and the constraints are kept so that
  submission remains possible". No claim that the project will or will not
  submit.
- **D-6 — Fix the source docs, not just the mirrors.** CLAUDE.md's
  Constraints and Technology Stack sections are GSD-managed blocks generated
  from `.planning/PROJECT.md` and `.planning/research/STACK.md`. Editing
  only the mirror would be reverted by the next `/gsd-docs-update`. Each
  mirrored edit is therefore made in both places, byte-identical. The
  Release Process section is hand-maintained in CLAUDE.md and has no source.
- **D-7 — One governing line beats a dozen rewritten table cells.** Rather
  than rewording every "EGO reviewers will reject it" cell, a single status
  line is placed immediately above the "What NOT to Use" table. It governs
  every cell below it, keeps the guidance intact, and is the narrowest edit
  that removes the false framing.

### README

`README.md:45-47` heads the install section with **"From extensions.gnome.org
(recommended)"** and *"(EGO listing pending review — link will land here once
approved.)"*. That misinstructs a user twice: it points them at a channel
where USBee cannot be found, and it asserts a review that is not underway.
**Changed** — the GitHub Release becomes the recommended path.

`.github/workflows/ci.yml:11` names a job "EGO pre-check (shexli)". That is a
lint that runs and passes; keeping it is exactly the "EGO-compatible by
choice" posture. **Unchanged, reported.** `.github/workflows/release.yml`
contains no EGO reference at all — it already ends at the GitHub Release.
