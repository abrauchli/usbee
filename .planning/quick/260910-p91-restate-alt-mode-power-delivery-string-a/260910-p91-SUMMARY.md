## Part 1 — the alt-mode Power Delivery string

### Final string

```
Alt mode did not start — this connection does not provide USB Power
Delivery, which needs both a port and a cable that support it
```

`usbee@bitcreed.us/src/popover.js:618`, replacing

```
Alt mode failed: no USB-PD on this connection — use a USB-C port and cable
that support Power Delivery
```

### What is no longer claimed

Only the imperative. The row still fires on exactly the same gate
(`usb_altmode_state == Unsuccessful` ∧ `usb_altmode_failure` ∋ `no_usb_pd`),
still carries the amber warning class, and still names the SVID through the
transport-pill vocabulary. The *information* was never the problem: unlike
the three claims withdrawn before it, this one rests on a cause the daemon
asserts by name, and a PD connection definitionally needs a capable port and
a capable cable.

What is withdrawn is the promise that acting on it is possible. On the
development machine there is no PD controller at all (`/sys/class/typec` is
absent), so "use a USB-C port and cable that support Power Delivery"
resolves to "buy a different motherboard" — an instruction to do something
the reader may have no path to, phrased as though they do.

### Voice

Matched to what the three prior tasks settled on: declarative, fact then
elaboration across an em dash.

### Left standing, deliberately

- `CLAUDE.md:19` (GPL-3.0 "matches GNOME ecosystem norms and EGO
  expectations") and `:32` (the `org.gnome.shell.extensions.*` namespace
  "mandated by EGO's `shexli` lint") — both true, both reasons for a choice
  rather than claims of an active review, and both now sit in the same
  bullet list as the new Distribution bullet.
- The Version Compatibility, Confidence Notes and Sources rows that mention
  EGO — statements about EGO's own rules, not about USBee's status.
- `.github/workflows/ci.yml:11` "EGO pre-check (shexli)" — a lint that runs
  and passes. Keeping it *is* the EGO-compatible-by-choice posture, and
  renaming the job would churn CI history for nothing.
- `CHANGELOG.md`'s "the EGO `version` integer" — the `metadata.json` field
  is literally named for EGO's requirement.

### Neutral on intent

Every new sentence is true whether submission is abandoned or merely
deferred. Nothing asserts the project will or will not submit.

### Why the source docs were edited too

CLAUDE.md's Constraints and Technology Stack sections are GSD-managed
mirrors (`<!-- GSD:project-start source:PROJECT.md -->`,
`<!-- GSD:stack-start source:research/STACK.md -->`). Editing only the
mirror would have been reverted by the next `/gsd-docs-update`, so each
mirrored edit was made in both places and verified byte-identical. The
Release Process section is hand-maintained and has no source document.

### `.github/workflows/`

`release.yml` contains no EGO reference at all and already terminates at the
GitHub Release — it never needed changing, which is what made step 6 a pure
documentation error rather than a process one.
