# Quick Task 260915-ib9 — Remove the dead `SnapshotJson` interface declaration

## Problem

`SnapshotJson` is declared in USBee's inlined `IFACE_XML` literal
(`src/dbus-client.js`) and in the reference copy `dbus-iface.xml`, but USBee
has never called it and no feature stands on it. The user has decided it is
dead weight.

## Evidence it is genuinely dead

`rtk proxy grep -rn "SnapshotJson" usbee@bitcreed.us/ tests/` returns exactly
four hits, and a call-shaped grep
(`SnapshotJson(Async|Sync|Remote)?\s*\(`) returns none:

| Hit | Kind |
|-----|------|
| `src/dbus-client.js:62` | the declaration being removed |
| `dbus-iface.xml:15` | the reference copy being removed |
| `src/property-policy.js:15` | prose, about the **daemon's** method |
| `src/property-policy.js:38` | prose, about the **daemon's** method |

The two prose mentions stay accurate and are left alone: they tell a reader
that wire-only keys remain reachable *through the daemon*, and usbeehive
continues to export `SnapshotJson` regardless of what USBee declares.

## Tasks

1. Remove the `SnapshotJson` method from the `IFACE_XML` literal in
   `usbee@bitcreed.us/src/dbus-client.js`.
2. Remove it from `usbee@bitcreed.us/dbus-iface.xml`.
3. Extend the comment above `IFACE_XML` to say why `SnapshotJson` went while
   `Refresh` and `Diagnose` — also uncalled — deliberately stay.
4. Guard the removal in `tests/forward-compat.test.js`, and assert `Refresh`
   and `Diagnose` survive.
5. `CHANGELOG.md` entry under `## [Unreleased]`.

## Invariant to preserve

`dbus-iface.xml` is kept **byte-equal** to the `IFACE_XML` literal less the
doctype. `tests/forward-compat.test.js` already asserts this; both files must
therefore drop the method together. Verified by running the suite, not by
inspection.

## Explicitly out of scope

- **No usbeehive change.** The daemon may keep serving the method; this is
  only USBee's client-side declaration.
- No version bump, no tag, no push.
