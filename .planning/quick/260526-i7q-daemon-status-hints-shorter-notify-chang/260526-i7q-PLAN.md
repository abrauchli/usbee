<objective>
Two atomic, commit-separable fixes bundled as a single quick task:

1. Surface three distinct daemon states in the popover empty-state — currently the extension shows the same "Start usbeehived" hint whether the service unit file is installed or not. Users without `usbeehive` installed need the install command; users with an outdated install need the cargo update command (the existing "too old" copy says "restart", which is wrong for the actual workflow).

2. Shorten the `device-change-notify-scope` ComboRow item labels in `prefs.js`. The collapsed-state selected-value display is truncated at default prefs-window width; the row title itself is fine, but the option strings are 30–40 chars and overflow.

Purpose: One-screen-glance recovery for users who don't have usbeehive yet, accurate update hint for outdated users, and a tidy prefs ComboRow that doesn't ellipsize.

Output: Modified `empty-state.js` (new builder + unit-file probe), `tile.js` (three-way routing in `_rebuildPopover`), `prefs.js` (shorter `scopeChoices` labels).
</objective>

       1. Add a new exported function `isUsbeehiveServiceInstalled()` that returns a boolean. Use `Gio.File.new_for_path(path).query_exists(null)` (synchronous, local filesystem only — safe per D-15 because it's a stat() on a small known set of paths, not a D-Bus or network call). Probe these three locations in order and return `true` on the first hit:
          - `${GLib.get_user_data_dir()}/systemd/user/usbeehived.service`
          - `/usr/lib/systemd/user/usbeehived.service`
          - `/etc/systemd/user/usbeehived.service`
          Import `Gio` and `GLib` from `gi://Gio` and `gi://GLib` at the top of the file. Cache the result in a module-level `let _installedCache = null;` and a `let _cachedAt = 0;` timestamp; re-probe at most once every 30 seconds (a user installing usbeehive in a terminal while staring at the popover should see the state update on the next popover open, but we don't want to stat() on every keystroke). Provide an exported `invalidateInstalledCache()` for the future case where we wire it to a NameOwnerChanged event — not consumed in this commit, just exported for symmetry.

       2. Add a new exported function `buildDaemonNotInstalledItem()` that mirrors the shape of `buildEmptyStateItem()` and `buildDaemonOutOfDateItem()`: a `PopupMenu.PopupMenuItem` whose `.label.text` is `_('usbeehive not installed')` and whose body box contains:
          - hint label `_('Install usbeehive, then start it. This list will populate automatically:')`
          - a read-only selectable `St.Entry` whose text is the literal string `usbeehived --install-service`
          Reuse the same `usbee-empty-state` / `usbee-empty-state-body` / `usbee-empty-state-entry` style classes — no new CSS. Mirror the `entry.clutter_text.editable = false; entry.clutter_text.selectable = true;` pattern exactly.

       3. **Update the existing `buildDaemonOutOfDateItem()`**: the user's stated goal is "needs to be updated with `cargo install usbeehive --features=dbus`". The current copy points at `systemctl --user restart usbeehived` and the hint says "Update usbeehive, then restart it." Replace `RESTART_CMD` with the literal string `cargo install usbeehive --features=dbus` and change the hint label to `_('Update usbeehive, then restart the daemon. This list will populate automatically:')`. Keep the "restart" guidance in the hint prose (users still need to restart the unit after `cargo install`) but the copy-pasteable entry is the install command, which is what the user asked for and is the actionable bit. All user-visible strings remain `_()`-wrapped.

    B. In `usbee@bitcreed.us/src/tile.js`:

       1. Add `populateNotInstalledState` and `isUsbeehiveServiceInstalled` to the import from `./popover.js` and `./empty-state.js` respectively. Add a sibling `populateNotInstalledState(section)` export in `usbee@bitcreed.us/src/popover.js` that calls `section.removeAll(); section.addMenuItem(buildDaemonNotInstalledItem());` (same shape as `populateEmptyState` / `populateOutOfDateState`). Import `buildDaemonNotInstalledItem` from `./empty-state.js` in `popover.js`.

       2. In `_rebuildPopover()`, change the routing chain from the current two-way (`_daemonTooOld` → empty → device rows) to three-way:
          - `if (this._daemonTooOld)` → `populateOutOfDateState` (unchanged, highest precedence — daemon IS reachable, we know its version)
          - `else if (!this._store.daemonRunning)`:
            - if `!isUsbeehiveServiceInstalled()` → `populateNotInstalledState(this._rowsSection)`
            - else → `populateEmptyState(this._rowsSection)` (existing path)

          The `n = -1` / header-title computation at the bottom of `_rebuildPopover` stays as-is; both new-empty branches set `n = -1` implicitly (they don't assign to `n`).

    Do NOT spawn a subprocess to check service status. Do NOT use `Gio.Subprocess` against systemctl. Do NOT make this async — `query_exists()` is the documented synchronous local-stat primitive and is what gnome-shell itself uses for icon-theme lookups. EGO PACK-05 prohibits binary execution, not local file stats.

    All new user-visible strings go through `gettext as _` (the `cargo install ...` command itself is a literal — same convention as the existing `SYSTEMCTL_CMD` / `RESTART_CMD` constants, which are NOT `_()`-wrapped because they're literal commands, not prose).

    In `usbee@bitcreed.us/prefs.js` `_buildGeneralGroup()`, the `scopeChoices` array currently contains three labels of 30–40 chars each. The user reports the ComboRow truncates in both collapsed (selected-value display) and expanded (dropdown items) states. Adw.ComboRow's collapsed-state selected-value display gets roughly the right half of the row width — ~150-200 px in the default prefs window — which fits about 22-26 chars before ellipsizing.

    Shorten the labels (keep the GSettings `value` strings — `all` / `power` / `off` — untouched; only the display labels change):

      - `'all'`   → `_('All device changes')`             (was: "Notify on all device changes" — 29 chars → 19 chars)
      - `'power'` → `_('Charging-relevant only')`         (was: "Notify only on charging-relevant changes" — 40 chars → 22 chars)
      - `'off'`   → `_('Off')`                            (was: "Do not notify on device changes" — 31 chars → 3 chars)

    The row title `_('Notify on device changes')` already carries the verb context, so the option strings can drop the "Notify..." prefix without losing meaning — and the subtitle `_('Toasts when a USB device is connected or disconnected')` reinforces what the choices govern. This mirrors the GNOME settings convention for similar enum rows (Privacy → "File History & Trash" → "Off" / "1 day" / "7 days" — no verb in the choice).

    The row title itself (`_('Notify on device changes')`, 24 chars) fits in the left column at the default prefs window width; do not change it.

    The shortened labels are still wrapped in `_()` so the `.pot` regenerates correctly; the .pot itself will be regenerated separately during the next release-prep step (out of scope for this quick task — per STATE.md the .pot was already regenerated in 1306c09).

    Do not touch the GSettings schema XML — only the user-facing label strings change. The `value` strings ('all', 'power', 'off') are the schema-bound identifiers and must not change.
