1. **Device-change notifications** — surface every `DeviceAdded` / `DeviceRemoved` D-Bus signal as a transient MessageTray toast ("Connected: <headline>" / "Disconnected: <headline>"), gated by a new GSettings enum `device-change-notify-scope` ∈ {`all`, `power`, `off`} (default `all`). Forward-compat: unknown keys always render (gate is deny-list, not allow-list).

    1. `DeviceAdded` handler — signal payload is `(s id, s headline)` per IFACE_XML lines 90-93. Destructure:
       ```
       (_proxy, _sender, [id, headline]) => {
           // DeviceStore lookup is racy here — the daemon may not have
           // emitted ListDevices yet for this id. We still need a `kind`
           // for the 'power' scope filter, so try the store but fall back
           // to undefined (which the Notifier treats as default-allow).
           const dev = this._store?.devices?.find(d => d.id === id);
           const kind = dev ? {category: dev.category, deviceClass: dev.device_class} : undefined;
           this._notifier?.onDeviceAdded(id, headline, kind);
           this._scheduleRefresh();
       }
       ```

    2. `DeviceRemoved` handler — signal payload is `(s id)` only. The headline must be resolved BEFORE `_scheduleRefresh()` mutates the store. Do the lookup synchronously against the current `this._store.devices` snapshot:
       ```
       (_proxy, _sender, [id]) => {
           const dev = this._store?.devices?.find(d => d.id === id);
           const headline = dev?.headline || id;  // fallback to id when unknown
           const kind = dev ? {category: dev.category, deviceClass: dev.device_class} : undefined;
           this._notifier?.onDeviceRemoved(id, headline, kind);
           this._scheduleRefresh();
       }
       ```

       Critical ordering: the Notifier call MUST happen before `_scheduleRefresh()` (which the 150 ms debounce defers anyway, but we want the synchronous read of the pre-removal snapshot to be explicit at the call site).

       Note that `_snapshotImmediate()` itself is async (callback-driven `ListDevicesRemote`), so the snapshot is in fact replaced asynchronously — there is no race where the synchronous handler runs against a partially-mutated store. The 150 ms debounce gives additional headroom.

    Keep the existing registry tracking — `this._registry.addProxySignal(this._proxy, addedId/removedId)`. No new registry types needed.
