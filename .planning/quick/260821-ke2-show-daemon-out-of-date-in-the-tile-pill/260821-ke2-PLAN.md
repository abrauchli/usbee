<objective>
Make the "daemon out of date" state honest and actionable everywhere it
surfaces.

Today the Quick Settings pill says **"Daemon not running"** while the very
same popover, when expanded, says **"usbeehive daemon out of date"**. The
cause is two sources of truth: `DBusClient._onAppeared` calls
`store.setDaemonRunning(false)` right before emitting `daemon-too-old`, and
`DeviceStore.tileText` derives the pill from that boolean, while `tile.js`
routes the popover from its own private `_daemonTooOld` latch.

This plan collapses those into one store-owned tri-state, then uses it to
tell the user what they actually need to know: which usbeehive version
USBee requires, which one it detected, and the exact command to fix it —
with a copy button, in both the Shell popover and the preferences window.

Purpose: a user staring at "Daemon not running" while `systemctl --user
status usbeehived` says the daemon is up has no path forward. Showing
"requires 0.10.0 or newer — detected 0.11.0" turns a dead end into a
diagnosable fact.

Output: a new dependency-free `src/daemon-status.js` shared across both
processes, a tri-state `DeviceStore`, version-aware popover + prefs copy,
the new update command with clipboard buttons, CI-safe regression tests, a
regenerated `.pot`, and a CHANGELOG entry.
</objective>

<constraints_and_followups>
## Hard constraints (verified during planning)

- **C1 — `MIN_USBEEHIVE_VERSION` stays `'0.10.0'`.** Do not bump it, do not
  bump `metadata.json` `version` / `version-name`. The live daemon reports
  `0.11.0`, which already satisfies the minimum.
- **C2 — `isVersionAtLeast` keeps its fail-closed semantics** verbatim
  (`04-01-ADR-daemon-version-gate`): any non-3-part / non-integer /
  non-string input returns `false`. It is being MOVED, not rewritten.
- **C3 — the version gate stays where it is** (inside the proxy-construction
  callback). Do NOT add it to `_onProxyOwnerAcquired`: the proxy's cached
  `Version` may not have refreshed at the moment `notify::g-name-owner`
  fires, and a fail-closed read there would strand a healthy daemon in the
  out-of-date state with nothing left to re-drive it.
- **C4 — CI runs `gjs -m tests/*.test.js` in a bare gjs with no gnome-shell
  resources.** `src/dbus-client.js` must keep importing ONLY `gi://` modules
  plus the new zero-import module. Importing `device-store.js` (which pulls
  `resource:///org/gnome/shell/extensions/extension.js` for gettext) from
  `dbus-client.js` would silently break `tests/dbus-client.test.js` in CI.
  This is exactly why `DaemonState` lives in `daemon-status.js`, not in
  `device-store.js`.
- **C5 — `prefs.js` is the only file allowed to import `gi://Gtk` or
  `gi://Adw`** (CLAUDE.md C-03 / D-17), and it runs in a separate process
  where the Shell extension resource URI does not resolve. It may import
  `./src/daemon-status.js` precisely because that module imports nothing.
- **C6 — no subprocess spawning** (D-18 / EGO PACK-05). The update command
  is displayed and copied to the clipboard; it is never executed.
- **C7 — every user-visible string goes through `_()`** and uses
  `.format()` for interpolation, never string concatenation.

## Documented follow-ups — NOT work in this plan

Record these in the SUMMARY. Do not implement them here.

- **F1 — the observed out-of-date state is a false positive.** usbeehive
  0.11.0 ≥ 0.10.0, so the gate should pass. The most likely trigger is
  `this._proxy.Version` reading `undefined` at proxy-construction time,
  which fail-closes to `daemon-too-old`. After this plan the popover and
  prefs will say "detected unknown", which makes the misdiagnosis legible
  instead of silent. A real fix (re-reading `Version` via
  `get_cached_property` after `g-properties-changed`, or a `GetRemote`
  fallback) is deliberately out of scope.
- **F2 — the gate is not re-applied on owner re-acquire.** Restarting a
  genuinely too-old daemon flips the store to running without a re-check.
  Unchanged by design, per C3.
</constraints_and_followups>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| session bus → Shell process | Any session process can own `org.usbeehive.Devices`. Its `Version` property is attacker-influencable string data that this plan newly renders into the popover UI. |
| session bus → prefs process | Same string, rendered into an Adwaita subtitle, which parses Pango markup. |
| extension → user clipboard | The copy buttons write into the user's clipboard, which the user is expected to paste into a shell. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-ke2-01 | Spoofing / Tampering | Daemon `Version` string rendered in `empty-state.js` and `prefs.js` | low | mitigate | Clamp to the first 32 characters in both processes; in `prefs.js` additionally wrap in `GLib.markup_escape_text()` before it reaches an Adwaita subtitle, since Adwaita subtitles parse Pango markup (including `<a href>`). Shell-side `St.Label` does not enable markup, so the clamp suffices there. |
| T-ke2-02 | Tampering | Clipboard write from both copy buttons | low | accept | The copied text is the module constant `UPDATE_CMD` (plus the two existing fixed commands) — never daemon-supplied or user-supplied data, so no interpolation path exists into the clipboard. |
| T-ke2-03 | Elevation of Privilege | Displayed `cargo install … && systemctl --user restart usbeehived` | low | mitigate | The command is displayed and copied only. No `Gio.Subprocess`, no spawn, per D-18 / EGO PACK-05. The user runs it themselves in their own shell, so the extension never gains execution it did not already have. |
| T-ke2-04 | Denial of Service | Copy-feedback `GLib.timeout_add` sources in the Shell process | low | mitigate | Every pending source id is tracked and removed on the button's `destroy` signal (Shell) and on `close-request` (prefs), so a popover rebuild or lock/unlock cycle cannot leak sources or raise GLib-CRITICAL. |
| T-ke2-SC | Tampering | npm/pip/cargo installs | n/a | accept | This plan performs no package-manager installs. `usbee` is a pure-GJS extension with no dependency manifest; the cargo command is UI text, never executed. No `## Package Legitimacy Audit` is therefore required. |
