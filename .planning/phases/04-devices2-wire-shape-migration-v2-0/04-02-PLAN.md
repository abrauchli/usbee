DeviceEntry tuple (19 fields, in order):
  0  id                (s)
  1  category          (s)   - 'Hub' | 'TypeCPort' | 'UsbDevice'
  2  device_class      (s)   - 19 variants; 'Unknown' for TypeCPort
  3  device_subclass   (s)   - daemon-curated, may be empty
  4  status            (s)   - existing values + new 'Sourcing'
  5  headline          (s)
  6  subtitle          (s)
  7  icon              (s)
  8  vendor            (s)
  9  product           (s)
  10 vendor_id         (q)   - uint16
  11 product_id        (q)   - uint16
  12 primary_driver    (s)   - empty when unbound
  13 properties        (a(ss)) - flat (machine_key, value) pairs
  14 port_number       (i)   - -1 if not Type-C
  15 link_speed_mbps   (u)   - Mbit/s
  16 usb_version       (s)   - '2.0' | '3.2' | '4.0' | ''
  17 power             (uus) - (power_in_mw, power_out_mw, power_role)
  18 charging_diag     (bsssb) - (present, bottleneck, summary, detail, is_warning)

Diagnose(port) return shape: (bsssb) - same as charging_diag.

Status values (existing + new): Empty, Connected, Active, Charging, Sourcing.
power_role values: Source, Sink, DualRole, Unknown.
bottleneck values: NoCharger, ChargerLimit, CableLimit, DeviceLimit, Fine.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon→USBee | Session-bus messages from `org.usbeehive.Devices`. The daemon is trusted upstream code but USBee renders into the privileged gnome-shell process — string and icon-name handling must remain defensive (T-01-02 / T-02-01 / T-03-01 carry forward). |
| upstream-version→USBee | Daemon `Version` D-Bus property is the gate input for COMPAT-01. A malformed/missing string must not crash the extension. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | Daemon `icon` field in `DeviceEntry` | mitigate | Existing `SYMBOLIC_ICON_RE` guard in `device-icon.js` is preserved verbatim. iconForDevice still validates before passing to `St.Icon.icon_name`. Carries forward T-03-01. |
| T-04-02 | Information disclosure | `device.vendor` / `device.product` / `device.headline` / `device.subtitle` rendered into UI | mitigate | All daemon prose strings continue to land in `.text =` setters (never `.set_markup`) — preserves T-01-02 / T-02-01 mitigation. New code paths (label-table values, charging_diag.summary/detail) follow the same rule. |
| T-04-03 | Denial of service | Malformed `Version` string from daemon trips the gate parse | mitigate | Version-comparison rule from 04-01-ADR is fail-closed: any parse failure routes to `'daemon-too-old'`, never throws or crashes the extension. |
| T-04-04 | Tampering | Unknown enum value (`device_class`, `status`, `power_role`, `bottleneck`) | mitigate | WIRE-04 forward-compat — unknown enum values fall through to safe defaults. Asserted by `forward-compat.test.js` (Task 12). |
| T-04-05 | Denial of service | Unknown machine key in `properties: a(ss)` | mitigate | `labelForKey` (Plan 04-01) returns the raw key string for unknown lookups; row renders, never crashes. |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | This plan installs no third-party packages — pure JS source edits inside the existing GJS extension. No legitimacy audit required. |

    // Any parse failure returns false (the gate routes to 'daemon-too-old').
    function isVersionAtLeast(actual, minimum) {
        const parse = v => {
            if (typeof v !== 'string') return null;
            const parts = v.split('.').map(s => Number.parseInt(s, 10));
            if (parts.length !== 3 || parts.some(n => !Number.isInteger(n) || n < 0))

            if (a[i] > m[i]) return true;
            if (a[i] < m[i]) return false;
        }
        return true;
