  <files>.planning/phases/04-devices2-wire-shape-migration-v2-0/04-01-ADR-daemon-version-gate.md</files>
  <action>
    Create a one-page ADR titled "Daemon-version gate placement (Plan 04-01 prep for COMPAT-01/02)". Document the following decisions explicitly (these are derived from CONTEXT D-2.0-07 + RESEARCH §"Pattern: D-Bus proxy lifecycle"):

    1. **Constant location:** `MIN_USBEEHIVE_VERSION` lives in `usbee@bitcreed.us/src/dbus-client.js`, declared as a module-level `const` immediately after the existing `BUS_NAME` / `OBJECT_PATH` / `INTERFACE_NAME` triplet (lines 25-27). Placeholder value `"0.6.0"` per CONTEXT D-2.0-07; Plan 04-03 re-verifies the actual upstream tag at release time and may bump.

    2. **Check timing:** version comparison fires inside the existing `_onAppeared` proxy-construction callback in `dbus-client.js`, AFTER the `new UsbeehiveProxy(...)` callback resolves (so the proxy's cached property `Version` is populated), but BEFORE `this._store.setDaemonRunning(true)` is called. Reading the cached `Version` property does NOT issue a fresh D-Bus round-trip — `Gio.DBusProxy` caches it eagerly per the GJS proxy contract.

    3. **UI signal:** the DBusClient gains a fourth signal alongside `ready` / `lost` / `devices-changed`: a new `'daemon-too-old'` signal emitted instead of `ready` when the version check fails. The tile listens for it and routes to a new render path that calls `populateOutOfDateState(section)` (added in 04-02) instead of `populateDeviceRows` / `populateEmptyState`. Rationale for a distinct signal rather than overloading `'lost'` with a parameter: keeps Plan 04-02 diff small (one new branch, no parameter-shape change to existing consumers), and keeps the "out of date" state semantically separate from "vanished" — they have different copy and different recovery paths.

    4. **Version comparison rule:** simple lexical-tuple semver — split on `.`, parse each segment as integer, compare element-wise. Reject any `Version` string that fails to parse as `major.minor.patch` (treat as "out of date" — fail-closed for safety). Do NOT pull in a semver library; the daemon publishes strict semver per `env!("CARGO_PKG_VERSION")` (see `../usbeehive/src/dbus.rs:347-350`).

    5. **What the gate does NOT do:** it does not parameterise, does not feature-detect individual fields, does not allow override via GSettings. The constant is the single source of truth; bumping it is an EGO submission. This matches D-2.0-05.

    The ADR closes with a "Plan 04-02 wiring checklist" (5-7 bullets) the cutover task uses verbatim. NO code in this task — purely the planning doc.

    Commit message: `docs(04-01): ADR for daemon-version gate placement and signal name`
