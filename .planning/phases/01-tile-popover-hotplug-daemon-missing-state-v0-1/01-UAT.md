## Tests

### 1. Extension Installed & Discoverable
expected: After symlinking the extension folder into `~/.local/share/gnome-shell/extensions/` and re-logging the GNOME session, `gnome-extensions list | grep usbee` prints `usbee@bitcreed.us`.
result: pass

### 2. STATE-01 — Tile with "Daemon Not Running"
expected: With the usbeehive daemon stopped (`pgrep -f usbeehived` returns nothing), running `gnome-extensions enable usbee@bitcreed.us` and opening Quick Settings (Super+S) shows a tile labelled **USBee** with subtitle **Daemon not running**. The tile sits alongside Wi-Fi / Bluetooth / Sound.
result: pass
notes: |
  Initial failure surfaced a real bug — `dbus-client.js:76` used `Gio._promisify` on a `makeProxyWrapper`-generated proxy (wrong API: those proxies expose `*Remote()`, not `*Async()`/`*Finish()`), and the call site at line 164 invoked `ListDevicesAsync()`. Fixed inline (per user direction "2"): removed the `_promisify` line entirely and changed the call to `await this._proxy.ListDevicesRemote()`. User confirmed pass after switching to Xorg session (the prior Wayland session had a stale cached module).

### 3. STATE-01 — Empty-State Popover & Copyable Command
expected: Clicking the USBee tile opens a popover with header **USB devices** and a single row showing title `usbeehive daemon not running`, hint `Run this command, then this list will populate automatically:`, and a focusable read-only text field containing `systemctl --user enable --now usbeehive`. Selecting the field and Ctrl+A / Ctrl+C puts that exact command on the clipboard (paste anywhere to verify).
result: pass
notes: |
  Popover rendered correctly and the command copied to clipboard. Running it failed downstream with `Unit file usbeehive.service does not exist` — confirmed via search that usbeehive does NOT ship a systemd unit yet. Not a USBee bug. Tracked as a cross-project packaging gap (see Gaps → cross-project).

### 4. STATE-02 — Daemon Appears Mid-Session
expected: With the extension still enabled, starting the daemon (`cargo run --release --no-default-features --features dbus --bin usbeehived` from `../usbeehive`) and re-opening the popover within a few seconds: tile subtitle changes from **Daemon not running** to **Nothing connected** (or **N devices** / **1 device** if any USB devices are attached); popover shows `No USB devices attached` or headline-only device rows. No `JS ERROR.*usbee` / `already disposed` / `has no handler` lines appear in `journalctl --user /usr/bin/gnome-shell` since the baseline.
result: pass
notes: |
  Required a second inline fix beyond the XML signature: in GJS 1.80 (GNOME 46), `*Remote()` methods generated by `makeProxyWrapper` are callback-style, NOT Promise-style — calling without a callback returns `undefined` synchronously. Confirmed via the bundled `ubuntu-dock` extension's `nautilus.EmptyTrashRemote(...args, cb, cancellable)` usage. Wrapped the callback in a manual `new Promise` inside `_snapshotImmediate` (dbus-client.js:161). After reload, popover correctly lists all 12 attached devices (TP-Link UB500, Intel BT, MYSTIC LIGHT, hubs, USB LAN, Samsung monitor, Stream Deck Neo, Dell keyboard hub, Logitech mouse, etc.).

### 5. STATE-03 — Daemon Vanishes Mid-Session
expected: Killing the running daemon process and re-opening the popover after 1–2 seconds: tile subtitle reverts to **Daemon not running**; popover shows the empty-state row with the copyable command again. No usbee-related warnings or errors in the journal since the baseline.
result: pass

### 6. Clean Disable
expected: Running `gnome-extensions disable usbee@bitcreed.us` removes the USBee tile from Quick Settings while Wi-Fi / Bluetooth / Sound remain in place. `journalctl --user /usr/bin/gnome-shell` since the baseline contains no `already disposed` / `has no handler` / `JS ERROR.*usbee` entries.
result: pass
notes: |
  Extension state after disable: `Enabled: No`, `State: INACTIVE`. Tile disappeared, neighbors preserved. Zero teardown warnings in the journal since the post-reboot baseline — `SignalRegistry.dispose()` is doing its job (D-14). The only usbee log entry today is the pre-fix `TypeError` at 09:31:23 (before the callback-Promise wrap was loaded); no entries since.

- Test 4 (second root cause): `*Remote()` methods on `makeProxyWrapper` proxies are callback-style in GJS 1.80 (GNOME 46), not Promise-style. Calling without callback returned `undefined` synchronously → destructure threw `TypeError: undefined has no properties`. Wrapped the callback in a manual `new Promise` in `_snapshotImmediate` (dbus-client.js:161).
