## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| usbeehive → USBee | Daemon-supplied strings (`headline`, `subtitle`, `bullets[]`, `icon`) cross into the Shell process via session-bus D-Bus. Session bus has user-level trust (any session app can publish a name), so daemon payloads must be treated as untrusted-but-not-hostile. |
| User input → GSettings | `hide-empty-ports` and `port-mutes` are user-controlled but already exhaustively validated in Phase 02; this phase does not introduce a new GSettings consumer or producer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `device.icon` from daemon (UI-04 honours it as first-precedence icon name) | mitigate | `iconForDevice` applies defensive regex `/^[a-z0-9][a-z0-9-]*-symbolic$/i` — rejects shell metacharacters and non-symbolic names. If the daemon publishes a malicious string (e.g. an absolute path or shell injection), the regex rejects it and the local fallback table runs instead. `St.Icon.icon_name` is a name lookup against the system icon theme, not a path — even a regex bypass would only produce a missing-icon glyph, not code execution. |
| T-03-02 | Information Disclosure | Verbatim daemon prose in the new labelled-row right column | accept | Same risk profile as v1.0 — `bullets[]` already rendered verbatim via `.text = ...` (never `set_markup`). New code preserves this: all value-column `St.Label` instances are populated via `.text =` assignment. Pango parsing is never invoked on daemon-supplied prose. |
| T-03-03 | Denial of Service | Issue-first sort on every popover open | accept | O(n log n) over ~10-30 devices on a busy laptop. Even at n=100 (USB-tree-of-hubs pathological case) the sort is microseconds. D-11 lazy-populate ensures the sort runs only on tile-open, not on every `DeviceAdded` signal. |
| T-03-04 | Denial of Service | Per-row `open-state-changed` handlers accumulate over popover open/close cycles | mitigate | The handlers are connected to the per-row `PopupSubMenu` instances created inside `populateDeviceRows`. | T-03-05 | Tampering (supply-chain) | No new package installs; only system tools (`xgettext`, `gnome-extensions pack`, `glib-compile-schemas`) reused from Phase 02 | accept | No npm/pip/cargo dependency introduced.
